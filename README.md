# KanBarcode

ระบบบันทึกสถานะการส่งสินค้าด้วยเครื่องยิงบาร์โค้ด — **บริษัท เกาอาน จำกัด**

## ลิงก์ใช้งานจริง

**https://kan-barcode.vercel.app** ← ส่งลิงก์นี้ให้ผู้ใช้งาน

อย่าส่งลิงก์แบบ `kan-barcode-git-<branch>-<ทีม>.vercel.app` หรือ `kan-barcode-<ทีม>.vercel.app`
พวกนั้นเป็น URL ของ deployment ที่ถูก **Vercel Authentication** ป้องกันไว้
คนที่ไม่ได้ล็อกอินบัญชี Vercel ของเราจะถูกเด้งไปหน้าล็อกอินของ Vercel แทนที่จะเข้าเว็บ
(ปิดได้ที่ Vercel → Project → Settings → Deployment Protection)

## เปิดใช้งาน

ระบบ login ใช้ **Supabase** — ต้องตั้งค่าโปรเจกต์ Supabase ก่อนใช้งานครั้งแรก
ดูขั้นตอนทั้งหมดที่ [Docs/SUPABASE-SETUP.md](Docs/SUPABASE-SETUP.md) (ประมาณ 10 นาที)

**ทดสอบเครื่องตัวเอง** — ต้องเปิดผ่าน `http://` ไม่ใช่ `file://`

```
npx serve .
```

(อยากใช้การเชื่อมต่อ SQL Server ในเครื่องด้วย ให้ใช้ `npm start` แทน — ดูหัวข้อ "เชื่อมต่อ SQL Server")

**บน Vercel**

```
npm i -g vercel
vercel
```

หรือ push ขึ้น GitHub แล้ว Import Project ใน Vercel — ระบบจะติดตั้ง `mssql`
และ deploy ฟังก์ชันใน `api/` ให้อัตโนมัติ ไม่มี build step ฝั่งหน้าเว็บ

จากนั้นตั้ง **Settings → Environment Variables** สองตัวนี้ แล้ว **Redeploy หนึ่งครั้ง**

```
NEXT_PUBLIC_SUPABASE_URL       = https://xxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY  = eyJhbGciOi...
```

> เว็บนี้ไม่มี build step ตัวแปร `NEXT_PUBLIC_*` จึงไม่ถูกฝังตอน build เหมือน Next.js
> — `api/config.js` เป็นตัวอ่านค่าให้ตอน runtime แทน แต่ยังต้อง Redeploy หลังแก้ตัวแปรเหมือนกัน
> เพราะ Vercel ผูก environment variables ไว้กับ deployment

## เข้าสู่ระบบ

ล็อกอินด้วย **อีเมล + รหัสผ่าน** ผ่าน Supabase Auth

- บัญชี admin คนแรกสร้างที่ Supabase (ดู [Docs/SUPABASE-SETUP.md](Docs/SUPABASE-SETUP.md) ข้อ 4)
- ผู้ใช้คนอื่นให้ admin เพิ่มที่เมนู **สิทธิ์ผู้ใช้งาน** — ระบบสุ่มรหัสผ่านชั่วคราวมาให้
- ลืมรหัสผ่านกดลิงก์ที่หน้า login เพื่อรับลิงก์ตั้งรหัสผ่านใหม่ทางอีเมล
- เปลี่ยนรหัสผ่านตัวเองได้ที่ปุ่ม **เปลี่ยนรหัสผ่าน** มุมขวาบน

ไม่มีบัญชีเริ่มต้นแบบ fixed password อีกแล้ว — รหัสผ่านทั้งหมดถูก hash เก็บใน Supabase

## โครงสร้างไฟล์

```
index.html               เว็บทั้งระบบ (HTML + CSS + JS ในไฟล์เดียว)
api/config.js            ส่งค่า Supabase จาก Environment Variables ให้หน้าเว็บ
api/sqlserver.js         API เชื่อมต่อ SQL Server (ใช้ได้ทั้งบน Vercel และรันในเครื่อง)
local-server.js          รันเว็บ + API ในเครื่อง สำหรับ SQL Server ที่อยู่ในวง LAN (npm start)
sync-sql.js              ตัวดึงข้อมูลอัตโนมัติ SQL Server -> Supabase
sync-pick.bat            ตั้งค่าตัวดึง แบบเลือกฐานข้อมูล/View จากรายการจริง
sync-start.bat           รันตัวดึงค้างไว้
start-lan.bat            ดับเบิลคลิกเพื่อเปิดเซิร์ฟเวอร์ในวง LAN (เรียก local-server.js ให้)
supabase/schema.sql      ตาราง profiles + RLS + trigger (รันใน SQL Editor)
Docs/SUPABASE-SETUP.md   ขั้นตอนตั้งค่า Supabase ตั้งแต่ต้นจนจบ
Docs/KanBarcode.txt      ข้อกำหนดและบันทึกการพัฒนา
package.json             dependency ฝั่ง API (mssql)
.env.local.example       ตัวอย่าง Environment Variables (คัดลอกเป็น .env.local)
vercel.json              ตั้งค่า Vercel
```

## หน้าจอในระบบ

- **ภาพรวม** — สรุปสถานะประจำวัน
- **ยิงบาร์โค้ด** — เลือกรถ แล้วระบุเลขที่เอกสารเพื่ออัปเดตสถานะ
  (จัดเสร็จแล้ว → ส่งแล้ว → ถึงมือลูกค้าแล้ว)
  ระบุได้ 3 วิธี: ยิงบาร์โค้ด / พิมพ์เลขที่เอกสารเอง / กดปุ่ม ▾ เลือกจากรายการ
  ถ้าเลขที่เอกสารยังไม่มีในระบบ กดปุ่มในข้อความแจ้งเตือนเพื่อเพิ่มเข้าระบบได้ทันที
  (เพิ่มแล้วบันทึกสถานะเลย หรือกรอกรายละเอียดลูกค้า/ที่อยู่ก่อนก็ได้)
  (พิมพ์บางส่วนเพื่อค้นหาจากเลขที่เอกสาร ชื่อลูกค้า รหัสลูกค้า หรือจังหวัดก็ได้)
  เมื่อบันทึกแล้ว ทุกหน้า (ภาพรวม / เอกสาร / รายงาน) จะอัปเดตให้ทันที
- **จอแสดงผล** — จอสถานะเอกสารสำหรับเปิดค้างไว้หน้าคลัง แสดงเลขที่เอกสาร วันที่เอกสาร และสถานะ
  เลือกวันที่ได้ (หรือกด "ทุกวัน"), กด "อัปเดตข้อมูล" ได้เอง + อัปเดตอัตโนมัติทุก 15 วินาที,
  กดเต็มจอได้ และเอกสารสถานะ **จัดเสร็จแล้ว** จะเป็นสีเหลืองและกระพริบ
- **ปฏิทินรถ** — สถานะรถรายวัน (ว่าง / จองแล้ว / เดินทางอยู่) พร้อมเวลาไป-กลับ
- **แผนที่** — Google Map แสดงปลายทางตามวันที่ ระดับตำบล/อำเภอ/จังหวัด
- **เอกสาร** — รายการเอกสาร นำเข้าจาก Excel/CSV
- **เชื่อมต่อ SQL Server** — หน้าแยกต่างหาก เลือกได้ว่าจะนำเข้าไปหน้าไหน
  (ข้อมูลเอกสาร / รถและคนขับ / ปฏิทินรถ) แล้วเลือก Server → Database → Table หรือ View
- **ข้อมูลรถ** — ยี่ห้อ ทะเบียน คนขับ และรายละเอียดอื่น
- **รายงาน** — สรุปตามช่วงวันที่ ส่งออก CSV ได้
- **สิทธิ์ผู้ใช้งาน** — เพิ่ม/แก้ไข/ระงับผู้ใช้ กำหนดเมนูที่เข้าถึงได้ (admin เท่านั้น)

## นำเข้าจาก Excel

ไฟล์ต้องมีคอลัมน์: **แถว, เลขที่เอกสาร, วันที่เอกสาร, รหัสลูกค้า, ชื่อลูกค้า, ที่อยู่**
ระบบจะแยก ตำบล / อำเภอ / จังหวัด ออกจากที่อยู่ให้อัตโนมัติ (แก้ไขภายหลังได้)

## เชื่อมต่อ SQL Server

ใช้งานแบบเดียวกับ Excel → **Data** → **From Database** → **From SQL Server Database**
เมนู **เชื่อมต่อ SQL Server** (เป็นหน้าของตัวเอง) แล้วทำ 5 ขั้น

1. **ปลายทาง** — เลือกก่อนว่าจะนำเข้าไปหน้าไหน: ข้อมูลเอกสาร / รถและคนขับ / การจองรถ (ปฏิทินรถ)
2. **การเชื่อมต่อ** — เก็บรายการเชื่อมต่อไว้ได้หลายอัน แบบหน้าต่าง Create Connection ของโปรแกรมบัญชี
   (ตารางบอก Database / Company Name / Server-DSN / Provider) คลิกแถวเพื่อเรียกค่ากลับมา
   ปุ่ม **Test Connect** ทดสอบ, **Save** บันทึก, **Delete** ลบ, **ใช้การเชื่อมต่อนี้ →** ไปต่อ
   (รายการเชื่อมต่อเก็บไว้ในเครื่องนี้เท่านั้น ไม่ขึ้นคลาวด์ เพราะมีรหัสผ่าน SQL Server อยู่ด้วย)
   ฐานข้อมูลที่บริษัทใช้อยู่ (BC, kan, kowann, kowann58, tka, kan58 บนเซิร์ฟเวอร์ bcs-server)
   ถูกใส่ไว้ให้ตั้งแต่เปิดครั้งแรกทุกเครื่อง เหลือแค่กรอก Username / Password แล้วกด Save
   ถ้าเผลอลบไป กด **เพิ่มรายการตั้งต้น** เรียกคืนได้ (แก้รายชื่อได้ที่ตัวแปร `SQL_CONN_SEED` ใน index.html)
3. **ฐานข้อมูล** — ถ้ารายการที่เลือกระบุ Database ไว้แล้วจะข้ามขั้นนี้ไปเลย
   ไม่งั้นเลือกจากรายชื่อฐานข้อมูลที่บัญชีนี้เข้าถึงได้ (พิมพ์ชื่อเองก็ได้)
4. **ตาราง / วิว** — เลือก Table หรือ View จากรายการ (ค้นหาและกรองตามประเภทได้)
5. **นำเข้า** — ดูตัวอย่าง 50 แถวแรกพร้อมผลการจับคู่คอลัมน์ แล้วกดนำเข้า

คอลัมน์ที่ระบบอ่านของแต่ละปลายทาง (จับคู่ให้อัตโนมัติ ไม่สนตัวพิมพ์เล็กใหญ่)

| ปลายทาง | คอลัมน์ที่จำเป็น | คอลัมน์อื่นที่อ่านได้ |
|---|---|---|
| ข้อมูลเอกสาร | เลขที่เอกสาร (DocNo) | วันที่เอกสาร, รหัสลูกค้า, ชื่อลูกค้า, ที่อยู่, ตำบล, อำเภอ, จังหวัด |
| รถและคนขับ | รหัสรถ (หรือทะเบียน) | ยี่ห้อ, รุ่น, ทะเบียน, คนขับ, เบอร์โทร, ประเภทรถ, น้ำหนักบรรทุก, หมายเหตุ |
| การจองรถ | รหัสรถ + วันที่ | จังหวัด/ปลายทาง, เวลาออก, เวลากลับ, สถานะ, หมายเหตุ |

- **เอกสาร** จะพาไปหน้าตรวจสอบก่อนบันทึกเหมือนการนำเข้าจาก Excel
- **รถและคนขับ / การจองรถ** บันทึกทันทีหลังกดนำเข้า โดยเทียบจากรหัส — มีอยู่แล้วอัปเดตทับ ไม่มีเพิ่มใหม่
- การจองรถที่อ้างถึงรถที่ยังไม่มีในระบบจะถูกข้ามและแจ้งจำนวนให้ทราบ (นำเข้ารถก่อน)

ถ้าชื่อคอลัมน์ในฐานข้อมูลไม่ตรง ให้สร้าง View ใน SQL Server ที่ตั้งชื่อคอลัมน์ให้ตรงแล้วเลือก View นั้น

> รหัสผ่าน SQL Server จะถูกส่งไปที่ API เท่านั้น และจะเก็บไว้ในเบราว์เซอร์
> ก็ต่อเมื่อติ๊ก "จำรหัสผ่าน" เอาไว้

### ดึงข้อมูลอัตโนมัติ ไม่ต้องมีใครกดนำเข้า (sync-sql.js)

เหมาะกับกรณีอยากให้ทุกคนใช้ลิงก์ Vercel ได้ตลอด โดยไม่ต้องเปิดลิงก์ LAN เลย
ตัวดึงนี้รันเบื้องหลังบนคอมเครื่องไหนก็ได้ในออฟฟิศที่ Excel ต่อ SQL Server ได้อยู่แล้ว
**ไม่ต้องติดตั้งหรือแก้อะไรที่เครื่อง SQL Server**

**ตั้งค่าแบบเลือกจากรายการจริง ไม่ต้องพิมพ์ชื่อ View เอง** — ดับเบิลคลิก **`sync-pick.bat`**
(หรือสั่ง `node sync-sql.js --pick`) แล้วตอบตามที่ถามทีละข้อ

1. กรอก Server / Port / วิธีล็อกอิน / Username / Password
2. **เลือกฐานข้อมูล** จากรายการจริงบนเซิร์ฟเวอร์ (พิมพ์แค่หมายเลข)
3. เลือกปลายทาง — ข้อมูลเอกสาร หรือ รถและคนขับ
4. **เลือก Table / View** จากรายการจริง (มีให้พิมพ์คำค้นกรองถ้ารายการเยอะ)
5. ระบบอ่านคอลัมน์จริงมาให้ดู แล้วจับคู่อัตโนมัติ ช่องไหนเดาไม่ออกจะให้เลือกเอง
6. ตั้งชื่องาน + รอบเวลา + บัญชีที่ใช้เขียนข้อมูล → เขียนลง `sync-config.json` ให้เลย

จากนั้น

```
node sync-sql.js --once     ← ลองยิงจริงรอบเดียว ดูผลใน sync-sql.log
node sync-sql.js --list     ← แค่ดูรายชื่อฐานข้อมูล / View เฉย ๆ
```

ผ่านแล้วดับเบิลคลิก **`sync-start.bat`** ให้รันค้างไว้ (หรือวาง shortcut ใน `shell:startup` ให้เปิดเองตอนบูต)

จะแก้ `sync-config.json` ด้วยมือเองก็ได้ — ดูแม่แบบที่ `sync-config.example.json`

| ค่า | คือ |
|---|---|
| `sql.server` / `database` / `user` / `password` | ชุดเดียวกับที่กรอกใน Excel (`auth: "ntlm"` ถ้าใช้บัญชี Windows) |
| `supabase.email` / `password` | บัญชีในระบบ KanBarcode ที่มีสิทธิ์เมนู "ข้อมูลเอกสาร" (แนะนำสร้างบัญชีแยกไว้ใช้กับตัวดึงนี้) |
| `jobs[].view` | View/Table ที่จะดึง หรือใส่ `query` เป็น SQL เต็มก็ได้ |
| `jobs[].columns` | ระบุชื่อคอลัมน์เองเฉพาะอันที่ระบบจับคู่ให้อัตโนมัติไม่ได้ |
| `everyMinutes` | ดึงซ้ำทุกกี่นาที (ค่าเริ่มต้น 30) |

พฤติกรรมที่ออกแบบไว้กันข้อมูลหน้างานหาย

- เอกสาร **ใหม่** → เพิ่มให้พร้อมสถานะ "ยังไม่จัด"
- เอกสาร **ที่มีอยู่แล้ว** → อัปเดตเฉพาะรายละเอียด (ลูกค้า/ที่อยู่/วันที่) **ไม่แตะสถานะและรถที่ผูกไว้**
  เพราะสองอย่างนั้นมาจากการยิงบาร์โค้ดหน้างาน
- แถวที่หายไปจาก View **จะไม่ถูกลบ** ออกจากระบบ
- จำลายเซ็นข้อมูลรอบก่อนไว้ในไฟล์ `.sync-state.json` รอบถัดไปส่งเฉพาะแถวที่เปลี่ยนจริง
- บันทึกผลทุกรอบไว้ที่ `sync-sql.log`

### SQL Server อยู่ในวง LAN (ใช้ IP ภายใน เช่น 192.168.x.x)

**ทำไมต้องทำแบบนี้** — เว็บบน Vercel รันอยู่บนเครื่องของ Vercel ที่อยู่บนอินเทอร์เน็ต
คำสั่งต่อฐานข้อมูลจึงออกจากศูนย์ข้อมูลของ Vercel ไม่ได้ออกจากคอมของเรา
IP แบบ `192.168.x.x` เป็นเลขที่ใช้ได้เฉพาะภายในวงเน็ตเวิร์กของบริษัท
Vercel จึงหาเครื่อง SQL Server ไม่เจอ (ขึ้น `Failed to connect ... 192.168.x.x:1433`)

**ทางแก้ที่ง่ายที่สุด (ไม่ต้องติดตั้งอะไรเลย)** — ใช้ Excel เป็นตัวกลาง
ดึงข้อมูลใน Excel ตามที่ทำอยู่แล้ว (Data → From SQL Server) → Save As `.xlsx`
→ ลากไฟล์ไปวางที่แท็บ **นำเข้าจาก Excel** ในเว็บ จบ ใช้ลิงก์ Vercel ได้ตามปกติ
เหมาะกับการนำเข้าวันละครั้งสองครั้ง

**ทางแก้แบบต่อตรง (ตั้งครั้งเดียว ใช้ยาว)** — รันเว็บ + API บนคอมเครื่องหนึ่งในออฟฟิศ
เครื่องนั้นอยู่ในวงเดียวกับ SQL Server จึงต่อถึงแน่นอน แนะนำให้ใช้เครื่องที่เปิดค้างไว้อยู่แล้ว

1. ติดตั้ง [Node.js](https://nodejs.org) (รุ่น LTS) บนเครื่องนั้น — ครั้งเดียวจบ
2. คัดลอกโฟลเดอร์โปรเจกต์นี้ไปวางบนเครื่องนั้น
3. ดับเบิลคลิก **`start-lan.bat`** (ครั้งแรกจะติดตั้งไลบรารีให้เอง)
4. หน้าต่างคำสั่งจะบอกที่อยู่ เช่น `http://192.168.1.52:3000` ให้ทุกเครื่องในวงเปิดที่อยู่นี้
   และจะสร้างไฟล์ **`เปิด KanBarcode.url`** ไว้ในโฟลเดอร์ — ก๊อปไปวางหน้าจอเครื่องอื่นได้เลย
5. เข้าเมนู **ข้อมูลเอกสาร → เชื่อมต่อ SQL Server** ช่อง API Endpoint ใส่ `/api/sqlserver` ตามเดิม

ไม่ต้องตั้งค่า Supabase อะไรเพิ่ม — ค่าเชื่อมต่อฝังไว้ในหน้าเว็บแล้ว
(อยากชี้ไปโปรเจกต์ Supabase อื่นค่อยสร้างไฟล์ `.env.local` ทีหลังได้ ค่านั้นจะมาก่อนเสมอ)

เครื่องที่รันต้องเปิดค้างไว้ระหว่างใช้งาน (ปิดด้วย Ctrl+C) และถ้า Windows Firewall ถาม
ให้กด **Allow access** สำหรับ Private network ไม่งั้นเครื่องอื่นในวงจะเปิดไม่ได้

**ให้เปิดเองทุกครั้งที่เปิดเครื่อง** — กด `Win + R` พิมพ์ `shell:startup` แล้ว Enter
จากนั้นคัดลอก **shortcut** ของ `start-lan.bat` ไปวางในโฟลเดอร์ที่เปิดขึ้นมา

ล็อกอิน Supabase กับการซิงก์ข้อมูลยังทำงานปกติ เพราะเป็นการเรียกออกอินเทอร์เน็ตขาออกอย่างเดียว
ข้อมูลจึงเป็นชุดเดียวกับที่เปิดผ่าน Vercel

> อย่าเปิดเว็บจาก Vercel (https) แล้วชี้ API Endpoint ไปที่ `http://192.168.x.x`
> เบราว์เซอร์จะบล็อกเพราะเป็น mixed content (หน้า https เรียก http ไม่ได้)
> — ต้องเปิดเว็บจากเครื่องที่รัน `start-lan.bat` เท่านั้น

## ข้อมูลถูกเก็บที่ไหน

| ข้อมูล | เก็บที่ | ใช้ร่วมกันทุกเครื่อง |
|---|---|---|
| บัญชี อีเมล รหัสผ่าน (hash) | Supabase Auth (`auth.users`) | ใช่ |
| ชื่อ ระดับสิทธิ์ เมนู สถานะเปิด/ระงับ | Supabase (`public.profiles`) | ใช่ |
| เอกสารและสถานะที่ยิงบาร์โค้ด | Supabase (`public.documents`) | ใช่ |
| ประวัติการเปลี่ยนสถานะ | Supabase (`public.document_logs`) | ใช่ |
| รถและคนขับ | Supabase (`public.vehicles`) | ใช่ |
| การจองรถในปฏิทิน | Supabase (`public.bookings`) | ใช่ |
| Google Maps API key, ค่าเชื่อม SQL Server | `localStorage` ของเบราว์เซอร์ | ไม่ |

ข้อมูลหลักทั้งหมดอยู่บน Supabase แล้ว ทุกเครื่องเห็นชุดเดียวกัน
`localStorage` เหลือไว้เป็นสำเนาสำรองในเครื่อง (เปิดเว็บได้เร็วและยังดูข้อมูลได้ตอนเน็ตหลุด)

**วิธีทำงานของการซิงก์** — ทุกครั้งที่บันทึก ระบบเทียบข้อมูลกับภาพถ่ายล่าสุด
แล้วส่งขึ้น Supabase เฉพาะแถวที่เปลี่ยน (หน่วง 0.4 วินาที เผื่อยิงบาร์โค้ดรัว ๆ)
ส่งไม่สำเร็จจะมีป้ายสีแดงมุมขวาบน กดที่ป้ายเพื่อลองใหม่ได้ทันที

> ⚠ ถ้าอัปเดตเว็บมาจากเวอร์ชันก่อนหน้า ให้รัน [supabase/data-schema.sql](supabase/data-schema.sql)
> ใน Supabase → SQL Editor อีกหนึ่งรอบ (รันซ้ำได้ไม่เสียข้อมูล) เพื่อสร้าง unique index
> ของตาราง `document_logs` ที่ใช้กันประวัติสถานะซ้ำ

### ความปลอดภัยของ anon key

หน้าเว็บใช้แค่ **Project URL + anon public key** ซึ่งเป็นคีย์สาธารณะที่ออกแบบมาให้ฝังในหน้าเว็บได้
สิทธิ์จริงบังคับด้วย **Row Level Security** ที่ฝั่งฐานข้อมูล:

- ผู้ใช้ทั่วไปอ่านได้เฉพาะแถวของตัวเอง และแก้ไขอะไรไม่ได้เลย (เลื่อนขั้นตัวเองเป็น admin ไม่ได้)
- บัญชีที่สมัครเข้ามาเองจะถูกตั้งเป็น `active = false` เสมอ เข้าระบบไม่ได้จนกว่า admin จะอนุมัติ
- **ห้าม** นำ `service_role` key มาใส่ในหน้าเว็บ เพราะคีย์นั้นข้าม RLS ได้ทั้งหมด
